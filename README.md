# ReachCare

**Decision support and community outreach for free health clinics across the United States.** Built for HackNC.

A hospital selects a state, enters where it is and what it can run. ReachCare recommends potential host sites on a state map, lets the planner question the recommendation in plain language, and helps residents find proposed clinics and sign up for alerts.

## What it does

- **Plan:** select a state, then enter a hospital (Google Places autocomplete), radius, service, patient travel target, staffing, clinic days and dates. Returns potential sites, dates, capacity and estimated cost on a zoomable state map.
- **Ask:** a Gemini-powered chat explains why communities were prioritized and explores trade-offs between travel time, coverage and resources.
- **Alert:** residents sign up on a web page to be texted when a free clinic is scheduled nearby.
- **Text or talk:** residents text or send a voice note in any language. Text gets a text reply, and a voice note gets a voice reply in the same language.
- **Services:** blood-pressure, diabetes, and COPD/lung screening, plus asthma education and support.

## How the recommendation works

A transparent optimization, not a trained model.

```text
priority    = 0.7 × health_index + 0.3 × no_vehicle_index
need_weight = adults_18_plus × priority            (per census tract)
```

1. Score available census tracts in the selected state from Census ACS and CDC PLACES.
2. Keep tracts inside the hospital's radius and drop those near an existing HRSA health center when that option is enabled.
3. Greedily pick public library candidates that add the most uncovered need, one per clinic day.
4. Re-run for seven health-vs-transport weightings and report how often each site was chosen ("7 of 7 priority mixes").

Reach counts who lives near a site, not expected turnout.

## AI usage

| Service | Model | Used for |
| --- | --- | --- |
| **Google Gemini API** | `gemini-3.5-flash` (falls back to `gemini-3.1-flash-lite`, then `gemini-flash-latest`) | Plan explanations, planner chat, clinic question interpretation and grounded replies, translation |
| **ElevenLabs** | Scribe (`scribe_v2`) speech-to-text, `eleven_multilingual_v2` text-to-speech | Transcribing voice notes and detecting language; spoken replies |
| **Claude Code** (Anthropic) | n/a | AI coding assistant used during development |

Guardrails:

- Gemini only receives the plan's own data and a table of what-if scenarios computed by our model. It never supplies census figures, chooses sites or does the arithmetic.
- Replies say "within reach", never "served", and the bot declines medical advice.
- With no Gemini key the app still plans and maps; the bot falls back to rule-based matching.

Data: U.S. Census ACS 2024, CDC PLACES 2025, IMLS public library outlets FY2024, and HRSA health-center sites. The bundled catalog covers 50 states and DC. All figures are sourced from public datasets, never generated by AI.

## Nationwide data catalog

The bundled `data/us.sqlite3.gz` covers the 50 states and DC. It contains 83,522 CDC PLACES tracts joined to ACS 2024 adult population and households without a vehicle, 84,121 Census tract boundaries, 16,752 public library outlets, and 17,806 HRSA health-center sites. The 238 tracts without a usable vehicle-access estimate retain a missing value. Library facilities and health-center service details require local verification before use in a clinic plan.

The planner and map load the selected state's data from the catalog. State-scoped catalog reads are available at `/api/catalog/states`, `/api/catalog/tracts?state=CA`, `/api/catalog/libraries?state=CA`, `/api/catalog/health-centers?state=CA`, and `/api/catalog/geography?state=CA`. Record endpoints accept `limit` (up to 2,000) and `offset`. Travel minutes are estimates derived from straight-line coordinates and a fixed conversion factor.

To rebuild the catalog from public source files, run `python scripts/prepare_data.py`. Source URLs, retrieval times, and checksums are recorded in the data manifests.

## Run it

```sh
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # add your keys
(cd bot && npm install)
./start.sh                    # web app on http://127.0.0.1:8000 plus the iMessage bridge
```

Web app only: `python3 server.py`. Pages: `/` plan, `/#/docs` how it works, `/bot.html` bot tester, `/join.html` resident sign-up.

On localhost, the browser bot uses saved plans and the persistent local conversation store; `./start.sh` also runs the Photon bridge for real iMessages. On Vercel, the browser bot shows a preloaded example conversation with an English text exchange and a Spanish voice exchange. These example messages and audio files are static and do not call Gemini. Live browser questions use proposed plans created in the same browser and keep conversation state in that browser tab. With `GEMINI_API_KEY` set, Gemini interprets clinic questions and writes answers grounded in the matching plan; otherwise basic lookup replies remain available. The hosted Get alerts page is an interactive signup preview: it does not collect a phone number, save a subscriber, or send a message. Live voice notes in the browser require `ELEVENLABS_API_KEY` in the Vercel environment.

The planner chat asks Gemini to explain the active plan. The resident bot uses Gemini to interpret clinic questions and translate replies; when a saved plan matches, Gemini can also phrase the answer using that plan's facts. With no saved plans, the bot says it has no proposals to check. A proposed date or venue is not a confirmed clinic event.

Adding Photon credentials to Vercel alone does not enable live alerts. The current bridge runs continuously and keeps subscriptions and its outbox in a local JSON file. A hosted live version needs persistent subscriber storage, a Photon webhook for inbound messages and STOP requests, and outbound delivery from the hosted service. Until those pieces are configured, `/api/signup` remains disabled on Vercel.

Keys in `.env`: `GOOGLE_MAPS_API_KEY`, `GEMINI_API_KEY`, `ELEVENLABS_API_KEY`, `PHOTON_PROJECT_ID`, `PHOTON_PROJECT_SECRET`. Voice replies also need `ffmpeg`. Tests: `python3 -m unittest discover -s tests`.

## Privacy and limits

- Sign-up requires consent; `STOP` unsubscribes. No voice recordings or transcripts are stored.
- Hospital radius, clinic reach, and existing-care access use straight-line distance converted to estimated minutes, not real drive times.
- Health data are modeled estimates, and cost figures are placeholders.
- Library sites and health-center locations are candidate lists, not verified inventories of service offerings or availability.
